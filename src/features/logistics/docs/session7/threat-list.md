# Threat list: Logistics

| Question                                                                         | Our answer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Where does text from strangers enter our module?**                             | **`customerId`**: free text that comes from other modules (Storefront → Accounting → Logistics). The API accepts any non-empty string, stores it and returns it on every shipment, so it reaches every agent and page that reads shipments. This is our main entry point for an injected instruction. **`shippingAddress`** (`recipientName`, `street`, `city`, …): typed by customers. The API validates it but does **not store or return it** today, so it never reaches an agent. If addresses are stored later, they become an entry point too. `orderId`, `shipmentId`, `paymentReference`, `status` and timestamps are restricted by patterns or enums, so free text cannot get in there. Error messages we return contain only validated ids.                                                                                                                                                                                                                                                                                                      |
| **Which of our tools change data, and what is the worst a wrong call could do?** | **`apply_status_update`**: could mark a shipment `DELIVERED`, `CANCELLED` or `RETURNED` although nothing happened. Every update writes a permanent event, so the history would be wrong; the customer would see a false status and a `RETURNED` could start a refund elsewhere. **`create_shipment`**: could create a shipment for an order that was never paid; `paymentStatus: "PAID"` is only a claim in the message, Logistics cannot verify it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Which secrets does our module use, and where are they stored?**                | The model key (`LLM_API_KEY` / `CHAT_AI_API_KEY`) for the agent, and for the web gateway `LOGISTICS_API_TOKEN`, `LOGISTICS_DEMO_PASSWORD` and `LOGISTICS_DEMO_TOKEN`. All are read from environment variables only. `.env*` is in `.gitignore`; `.env.example` contains names, never values. The model never sees a key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **What protects each risk today?**                                               | **Business rules in the API:** only direct status steps (`IN_TRANSIT` cannot jump to `DELIVERED`), no step backwards, stale and duplicate updates rejected, one shipment per order. These stop impossible changes but not legal ones such as `CANCELLED` from `CREATED`. **Read-only MCP server (new, session 7):** for reading tasks the writing tools do not exist. **`readOnlyHint` annotations (new):** a host can ask for confirmation before each writing call. **Partner tokens (`demo_api.py`):** each team gets its own token and may only do what its role needs. Accounting may only create shipments; Storefront may only look up a shipment by order and read its history. Any other call gets 403, a missing token 401. `GET /shipping/methods` is public read-only checkout data. **Web gateway:** staff session and origin check before any write from the UI. **Open:** the plain `erp_logistics_api:app` (used by tests and the MCP server) has no authentication, so it must only run locally; payment is not verified with Accounting. |

## Safeguard we implemented

A **read-only configuration of the MCP server**: `mcp_server.py --read-only` registers only the four reading tools `get_shipment`, `list_shipments`, `get_shipment_events` and `list_shipping_methods`. It is listed as `logistics_ro` in `servers.json`. Evidence: `safeguard-evidence.md`.
